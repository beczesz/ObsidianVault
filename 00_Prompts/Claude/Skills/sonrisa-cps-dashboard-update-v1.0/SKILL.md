# CPS Dashboard Monthly Update (Phase 2)

Update `CPS - Dashboard - v2.xlsx` with monthly data using the Monthly Update Brief (MUB).

## How This Works

This skill is the LOGIC. The MUB is the DATA. Together they drive the dashboard update.

- **MUB** (`MUB_YYYY_MM.md`) is generated by Cowork during Phase 1. It contains per-project, per-person hours broken down to Dashboard granularity. Each project block includes a `**Dashboard:**` line mapping to the exact Client/Project name used in T&M Raw.
- **This skill** knows the dashboard structure, column mappings, formulas, state tracking, and the interactive update pattern.

The user attaches or pastes the MUB into Claude for Excel. This skill reads it and walks through each project, verifying or creating rows in T&M Raw.

## Architecture

```
MUB (the DATA)              +  This Skill (the LOGIC)
========================       ========================
Current month only:            Dashboard structure
  Project blocks               Column mappings A-AD
  Per-person hours              Formula templates
  Dashboard mapping             State tracking (AC/AD)
                                Interaction pattern
                                Previous month carry-forward
         |                              |
         v                              v
         Claude for Excel (open workbook)
         -> Per project: check, prefill, ACK loop
```

## Session Start -- Automatic Phase Detection

Every time a session starts (or resumes), the skill determines where to pick up:

1. Read the MUB (attached or pasted) to know the target month
2. Read T&M Raw for the current month, scan AC column
3. **If any T&M Raw rows for this month have AC = empty or PREFILLED** -> Phase 2.1 is not complete. Start/resume Phase 2.1.
4. **If ALL T&M Raw rows have AC = ACK (or ADJUSTED/SKIP)** -> Phase 2.1 is complete. Check Service Income:
   - Read Service Income for the current month, scan AE column
   - If Service Income is incomplete -> start/resume Phase 2.2
   - If Service Income is also complete -> check Phase 2.3:
5. **If Service Income is complete (all AE = ACK)** -> check Planned EDC, Planned PSIC, Actual PSIC:
   - If any sub-phase incomplete -> start/resume Phase 2.3
   - If all complete -> run Final Verification checks and report

This means: **each phase only runs after the previous one is fully ACK'd.** The user never has to manually trigger the next phase -- the skill detects it automatically.

## Resumability

The Status columns (AC in T&M Raw, AE in Service Income) make any session resumable. The MUB file is the entry point -- paste the same MUB in any session and the skill picks up where you left off.

**T&M Raw status (column AC):**

| AC Value | Meaning | Action |
|----------|---------|--------|
| (empty) | Not yet verified | Process this row |
| PREFILLED | Written but not reviewed | Present for review |
| ACK | Reviewed and confirmed | Skip |
| REVIEW | Needs discussion | Present issue first |
| ADJUSTED | Manually corrected after ACK | Skip |
| SKIP | Intentionally excluded | Skip |

**The user can re-run any time** by clearing the AC value on any row. The skill will re-check and re-PREFILL that row.

**Service Income status (column AE):**

| AE Value | Meaning | Action |
|----------|---------|--------|
| (empty) | Not yet verified | Process this row |
| PREFILLED | Written but not reviewed | Present for review |
| ACK | Reviewed and confirmed | Skip |
| REVIEW | Needs discussion | Present issue first |
| MISMATCH | Price doesn't match Clients contract | Flag for review |

**Column AF** is used for notes (same as AD in T&M Raw).

## Phase 2.1: T&M Raw Update

This is the main phase. It has three passes, done in order:

### Pass 1: Billable Project Rows

Go through each project in the MUB (in MUB order, which matches Dashboard order).

**For each MUB project block:**

1. **Read the `**Dashboard:**` line** to get the exact Client/Project name in T&M Raw
2. **Find matching rows** in T&M Raw for the current month (match on Client + Project + Year + Month)
3. **Three scenarios:**

**Scenario A: Row EXISTS and AC is empty**
- Verify the hours (col K) match the MUB person-hours
- If hours match: set AC = "PREFILLED", set AD = "verified"
- If hours differ: set AC = "PREFILLED", set AD = "MUB says Xh, dashboard has Yh"
- Announce: "Project [name]: [N] rows verified. [any mismatches]. OK?"
- User says OK -> set AC = "ACK" for all rows in this project
- User says something else -> set AC = "REVIEW" and note the concern

**Scenario B: Row EXISTS and AC = PREFILLED**
- Same as Scenario A: re-verify, present to user, wait for ACK

**Scenario C: Row DOES NOT EXIST (new project or person)**
- Look at previous month's T&M Raw for the same Client/Project/Person
- If previous month exists: carry forward all metadata (Type, Emp Status, E-level, Rate, Billable type, Discount) and update only Year, Month, #Month, and Hours from MUB
- If no previous month data: announce "New entry: [Person] on [Project]. I need: Type, E-level, Daily Rate, Billable type. What values?"
- Write the new row(s), set AC = "PREFILLED"
- Announce: "Added [N] new rows (rows X-Y). Please verify."
- Wait for ACK

**After each project:**
- User says "ok" / "ACK" -> set all project rows to ACK
- User says "review" or flags issue -> set to REVIEW
- Move to next project

### Pass 2: Internal Hours (FTE Employees)

After all billable projects are done, add internal hours for each FTE employee.

**Pattern from Dashboard (Feb example):**
- Columns A-D: Year, Month, Date ID formula, #Month
- Columns E-G: EMPTY (no Client, no Project, no Type)
- Column H: Person name (LastName FirstName format)
- Column I: Employee
- Column J: E-level
- Column K: Internal hours from MUB "Internal Hours per Person" section
- Column M: EMPTY (no rate for internal)
- Column P: "Internal"
- Column Q: 0

**Process:**
1. Read MUB "Hours Summary > Internal Hours per Person" section
2. For each FTE employee (NOT contractors) with internal hours > 0:
   - Check if an internal row already exists for this month
   - If exists and AC empty: verify hours, set PREFILLED
   - If not exists: create row following the pattern above
3. Announce: "Internal hours for [N] employees. [list names and hours]. OK?"
4. Wait for ACK

### Pass 3: Contractor Internal Hours

After FTE internal hours, add contractor internal rows.

**Pattern from Dashboard (Feb example, row 664):**
- Column E: "CPS"
- Column F: "Internal"
- Column G: "Fixed Price"
- Column H: Contractor name
- Column I: "Contractor"
- Column J: E-level
- Column K: Internal hours from MUB
- Column M: Contractor's daily rate (carry from previous month)
- Column P: "Billable" (yes, contractor internal is billed as Billable)
- Column Q: 0

**Process:**
1. Read MUB "Contractor Breakdowns" section for internal hours
2. For each contractor with internal hours > 0:
   - Check if a contractor internal row exists for this month
   - If exists and AC empty: verify hours, set PREFILLED
   - If not exists: carry forward from previous month, update hours
3. Announce: "Contractor internal: [name] [hours]h. OK?"
4. Wait for ACK

## Name Format

**Critical:** The MUB uses FirstName LastName format (Sontime convention, e.g., "Alexandru Ceclan"). The Dashboard uses LastName FirstName (Hungarian convention, e.g., "Ceclan Alexandru").

When matching MUB person names to Dashboard rows, reverse the name order. For three-part names like "Bálint Lajos Török", the Dashboard format is "Török Bálint Lajos".

## Phase 2.2: Service Income Update

After all T&M Raw rows are ACK'd, update the Service Income sheet. This sheet tracks fixed-fee revenue from contracts that are NOT purely T&M -- Fix Service, Hybrid, Fixed Price, and 24/7 Support contracts.

### How Service Income Works

The Service Income sheet (Sheet 8) has one row per client per month for each active fixed-fee contract. The data comes from two sources:

**Source A: Clients tab (Sheet 7)** -- the contract registry. Contains all client contracts with their type, fix price, currency, daily rate, start/end dates, and state.

**Source B: Previous month's Service Income** -- for carry-forward of recurring contracts.

### Service Income Column Map (A through AF)

| Col | Name | Source | Notes |
|-----|------|--------|-------|
| A | Year | Set | Integer (2026) |
| B | Month | Set | Integer 1-12 |
| C | Concatenated | Formula | `=A & " " & CHOOSE(B, "January", ...)` |
| D | Client | Clients tab or prev month | Must match Clients sheet col B |
| E | Project | Clients tab or prev month | Must match Clients sheet col C |
| F | Type | Clients tab col G | Fix Service, Hybrid, Fixed Price, 24/7 Support |
| G | Fix price Raw | Clients tab col H | Original currency amount |
| H | Fix price Currency | Clients tab col I | EUR, USD, HUF |
| I | Daily Rate Raw | Clients tab col J | For Hybrid: T&M overage rate |
| J | Rate Currency | Clients tab col K | EUR, USD, HUF |
| K | Fix Price (EUR) | Clients tab col L | EUR-converted fix price |
| L | Rate (EUR) | Clients tab col M | EUR-converted daily rate |
| M | Overage Hours | Manual or MUB | T&M hours above fixed scope (Hybrid) |
| N | Overage Fix | Manual | Fixed overage amount (if not hourly) |
| O | Overage Final | Formula | Calculated overage value |
| P | Revenue | Formula | Fix Price + Overage |
| Q-W | Profitability | Formulas | Client, Type, Costs, EDC, Profit, Margin, Quality |
| X | BU | Manual | Business unit (e.g., "CS" for shared clients) |
| Y | Income RAW | Manual | Other BU income share |
| Z | Currency | Manual | Currency for col Y |
| AA | Income Final | Formula | |
| AB | Total profit | Formula | |
| AC | Total Margin | Formula | |
| AD | Quality | Formula | |
| AE | Status | State tracking | PREFILLED / ACK / REVIEW / MISMATCH |
| AF | Notes | Free text | |

### Phase 2.2 Process

#### Step 1: Read Clients tab

Parse the Clients sheet (Sheet 7) and build a list of contracts that are:
- **State = "Delivery"** (column D)
- **Type** is one of: Fix Service, Hybrid, Fixed Price, 24/7 Support (column G)
- **Date range covers the current month**: Start date (col E) <= month end AND End date (col F) >= month start

Convert Excel serial dates: `datetime(1899, 12, 30) + timedelta(days=serial)`

#### Step 2: Read previous month's Service Income

Find all Service Income rows for the previous month (Year/Month match). These serve as templates for carry-forward.

#### Step 3: Read current month's Service Income

Find all existing rows for the current month. Check AE column for status.

#### Step 4: For each valid contract from Clients tab

**Scenario A: Row EXISTS in current month, AE is empty**
1. Verify the fix price matches the Clients tab contract:
   - Compare Fix price Raw (col G) and Currency (col H) against Clients tab col H and I
   - If match: set AE = "PREFILLED", AF = "verified against Clients row [N]"
   - If mismatch: set AE = "MISMATCH", AF = "Clients says [X], Service Income has [Y]"
2. Present to user for review

**Scenario B: Row EXISTS in current month, AE = PREFILLED**
- Same as Scenario A: re-verify, present, wait for ACK

**Scenario C: Row DOES NOT EXIST for current month**
1. Look at previous month's Service Income for the same Client/Project
2. If previous month exists: carry forward all fields, update only Year, Month, Concatenated
   - For Hybrid contracts: set Overage Hours (col M) to 0 (user fills in actual overage later)
3. If no previous month: create from Clients tab data:
   - Copy: Client, Project, Type, Fix price Raw, Currency, Daily Rate, Rate Currency, Fix Price EUR, Rate EUR
   - Set Overage fields to 0
   - Set Revenue = Fix Price EUR (for non-Hybrid) or formulas
4. Set AE = "PREFILLED"
5. Announce: "Added [Client] / [Project] ([Type], [Amount]). Please verify."

**After each contract:**
- User says "ok" / "ACK" -> set AE = "ACK"
- User flags issue -> set AE = "REVIEW"

#### Step 5: Anomaly Detection

After processing all contracts, run these checks:

1. **Missing contracts:** Contracts valid in Clients tab but no Service Income row created. Report these.
2. **Orphan rows:** Service Income rows for the current month that have no matching active contract in Clients tab. Flag as "No active contract found in Clients tab."
3. **Date mismatches:** Contracts where the end date has passed but state is still "Delivery."
4. **Price mismatches:** Where Service Income fix price differs from Clients tab fix price.
5. **Currency consistency:** Where currency in Service Income doesn't match Clients tab.

Present all anomalies to the user before finalizing.

#### Step 6: Summary

Report:
- Total Service Income rows for the month: [N]
- Total fixed revenue (EUR): [sum of col P]
- All rows AE = ACK: Yes/No
- Any anomalies found: [list]

## Phase 2.3: Planned EDC, Planned PSIC, and Actual PSIC

After Service Income is fully ACK'd, update the cost sheets. This phase has three sub-steps done in order.

### Phase 2.3a: Planned EDC (Planned External Direct Cost)

The Planned EDC sheet (Sheet 10) tracks subcontractor costs. One row per contractor per month.

**Column map (A through L):**

| Col | Name | Notes |
|-----|------|-------|
| A | Year | Integer |
| B | Month | Integer 1-12 |
| C | Concatenated | "YYYY MonthName" |
| D | Client | Optional -- which client the contractor works for |
| E | Project | Optional -- which project |
| F | Developer | Contractor name (LastName FirstName format) |
| G | Fix price Raw | Monthly cost amount |
| H | Fix price Currency | EUR, HUF, USD |
| I | Fix Price (EUR) | EUR-converted cost |
| J | Note | Free text |
| K | Status | PREFILLED / ACK / REVIEW (our addition) |
| L | Notes | Annotation (our addition) |

**Process:**

1. **Read previous month's Planned EDC** rows to know which contractors were billed last month
2. **Cross-reference with MUB** -- check "Contractor Breakdowns" section. If a contractor appears in the MUB but has no Planned EDC row, they may be new
3. **Cross-reference with T&M Raw** -- look at contractor rows (col I = "Contractor") to get the Daily Rate (col M). The monthly EDC can be inferred from: contractor's daily rate * working days, or from the previous month's EDC amount
4. **For each known contractor:**
   - If previous month EDC row exists: carry forward, set K = "PREFILLED"
   - If contractor is in MUB/T&M Raw but has no EDC history: announce "New contractor [Name] found in T&M Raw (rate = [X] EUR/day). What should the monthly EDC be?"
5. **Present all EDC rows** to user for review
6. Wait for ACK

### Phase 2.3b: Planned PSIC (Project Specific Indirect Costs)

The Planned PSIC sheet (Sheet 11) tracks project-specific costs that are not direct labor. Primarily MVMI 24/7 Support costs: availability payments, phone service, overtime provisions.

**Column map (A through M):**

| Col | Name | Notes |
|-----|------|-------|
| A | Year | Integer |
| B | Month | Integer 1-12 |
| C | Concatenated | "YYYY MonthName" |
| D | Client | e.g., "MVMI" |
| E | Project | e.g., "24_7 Support" |
| F | Developer | Optional -- person name |
| G | Type | Support Availability, Support Overtime, Phone Service |
| H | Fix price Raw | Amount in original currency |
| I | Fix price Currency | EUR, HUF |
| J | Fix Price (EUR) | EUR-converted amount |
| K | Note | Free text |
| L | Status | PREFILLED / ACK / REVIEW (our addition) |
| M | Notes | Annotation (our addition) |

**Process:**

1. **Read previous month's Planned PSIC** rows
2. **Carry forward recurring items** -- Support Availability and Phone Service typically repeat monthly with the same amounts
3. **For each previous month row:**
   - Create new row with updated Year/Month/Concatenated
   - Copy all other fields from previous month
   - Set L = "PREFILLED"
4. **Present all PSIC rows** to user
5. Wait for ACK

**Note:** The MUB does NOT contain PSIC data. This is purely carry-forward from the previous month. If the user has new PSIC items or changed amounts, they will tell you during the ACK step.

### Phase 2.3c: Actual PSIC

The Actual PSIC sheet (Sheet 12) tracks the actual realized costs. This sheet has the same column structure as Planned PSIC but with actual per-person breakdowns (e.g., each person's availability payment).

**This is manual work.** The data comes from a separate source (invoices, payroll) that the skill does not have access to.

**Process:**

1. **Remind the user:** "Actual PSIC for [Month] needs to be filled from the MVMI cost breakdown. This is manual -- do you have the data, or should we skip this for now?"
2. If the user provides data, help them enter the rows
3. If not, note it as pending and move on

**Important:** BU Dash1 column AA pulls from Actual PSIC via SUMIFS. If Actual PSIC is empty for the month, the profit calculation in BU Dash1 will be optimistic (missing costs).

## Final Verification

After all phases are complete:

**T&M Raw (Phase 2.1):**
1. Count total hours in new T&M Raw rows for the month
2. Compare with MUB total (Billable + Internal should match T&M Raw total)
3. Report: "T&M Raw total: Xh, MUB total: Yh. Match: Yes/No"
4. Check all rows have AC = ACK

**Service Income (Phase 2.2):**
1. Count Service Income rows for the month
2. Sum total fixed revenue (col P)
3. Verify all rows have AE = ACK
4. Verify every row has a valid contract in Clients tab
5. Report: "Service Income: [N] rows, [total] EUR. All ACK: Yes/No"

**Planned EDC & PSIC (Phase 2.3):**
1. Verify Planned EDC has rows for all active contractors
2. Verify Planned PSIC has recurring items carried forward
3. Note if Actual PSIC is still pending

## Post-Update Verification Checks

After all phases are complete, run these sanity checks on the Dashboard:

### Check 1: Contractor Margin = 0%

In T&M Raw, every contractor row (col I = "Contractor") should have Margin (col W) = 0% for the current month. This confirms that contractor costs are correctly offset by the Transfer Price lookup. If any contractor has non-zero margin, flag it.

### Check 2: CPS Dash V2 Month Column

Verify that the CPS Dash V2 sheet (Sheet 1) has a row for the current month with populated data. The row should have:
- Year/Month/Concatenated filled
- Contract counts (D-I) showing reasonable numbers
- Income rankings (Y/Z columns) and profit rankings (AC/AD/AE columns) populated
- If any ranking columns are empty, flag: "CPS Dash V2 row [N] has empty ranking columns -- needs manual update"

### Check 3: BU Dash1 Month Row

Verify that the BU Dash1 sheet (Sheet 3) has a row for the current month. Key columns to check:
- **J (Total Income):** Should be non-zero (formula: sum of D through I)
- **L (EDC):** Should match Planned EDC total for the month (formula pulls from Planned EDC)
- **M (PSIC):** Should match Planned PSIC total for the month (formula pulls from Planned PSIC)
- **X (Total Actual):** Sum of actual revenue columns S through W
- **AT (Logged hours):** Should match T&M Raw total hours for the month
- **AS (Reference hours):** Expected hours -- if empty, flag for manual entry
- If L=0 and Planned EDC has rows, the formula range may need extending
- If M=0 and Planned PSIC has rows, the formula range may need extending

### Check 4: Formula Range Coverage

BU Dash1 formulas reference specific ranges (e.g., `'T&M Raw'!$R$2:$R$1034`). If T&M Raw has grown beyond row 1034, the formulas will miss new rows. Check that the current month's T&M Raw rows fall within the formula ranges. Same for Service Income (`$K$2:$K$183`) and Planned EDC/PSIC (`$I$4:$I$196`).

### Reporting

Present all check results in a summary:
```
Final Verification:
- T&M Raw: X hours, MUB match: Yes/No, all ACK: Yes/No
- Service Income: N rows, total EUR, all ACK: Yes/No
- Planned EDC: N contractors, all ACK: Yes/No
- Planned PSIC: N items, all ACK: Yes/No
- Actual PSIC: [filled / pending]
- Contractor margins: all 0%: Yes/No [list exceptions]
- CPS Dash V2: row exists, rankings filled: Yes/No
- BU Dash1: row exists, EDC/PSIC populated: Yes/No
- Formula ranges: all covering current data: Yes/No
```
