# Termék testreszabás és preferencia mentés — Feature Spec v0.1

## 1. Problem Statement

Egy hagyományos kézműves húsüzletben a mészáros ismeri a törzsvásárlót: tudja, hogy Kati néni a darált húst soványabban szereti, a karajt vékonyra szeletelve kéri, és a csülköt mindig pácolatlanul viszi. Ez a személyes kapcsolat versenyelőny — de az online rendelés jelenlegi verziójában **teljesen hiányzik**.

A vásárló jelenleg nem tudja megadni, hogyan készítsék elő a terméket (szeletelés, pácolás, zsírosság, darálás), és a rendszer nem emlékszik a korábbi választásaira. Ez azt jelenti, hogy minden rendelés "idegen" érzésű marad — a "hentes beszélgetés" nem digitalizálódik.

**Ez a feature a DH legerősebb retention drivere lehet:** ha a rendszer "ismer engem", a váltási költség nő, a visszatérés természetessé válik.

## 2. Goals

| # | Cél | Mérés |
|---|-----|-------|
| G1 | A vásárló személyre szabhassa a terméket rendeléskor | ≥60% rendelésnél legalább 1 opció kiválasztva (30 napon belül beta után) |
| G2 | A rendszer megjegyezze a preferenciákat per user per termék | 2.+ rendelésnél az előző választás automatikusan megjelenik default-ként |
| G3 | Újrarendelésnél a preferenciák betöltődjenek | Reorder flow-ban 0 extra kattintás a visszatérő preferenciáknál |
| G4 | A vásárló érezze: "itt ismernek engem" | Kvalitatív feedback a beta-ban |
| G5 | A mészáros egyértelmű utasítást kapjon minden rendeléshez | Admin rendelés nézeten a preferenciák megjelennek |

## 3. Non-Goals

| # | Amit NEM csinálunk | Miért nem |
|---|---------------------|-----------|
| NG1 | AI-alapú preferencia javaslat | Nincs elég adat — v0.6+ |
| NG2 | Globális "profil" (pl. "vegetáriánus") | Túl komplex, nem releváns 37 terméknél |
| NG3 | Allergia/diéta szűrő | Jogi felelősség — nem vállalunk tanácsadást |
| NG4 | Árazás az altípus alapján (pl. szeletelés felár) | Phase 1-ben nincs felár — egyszerűség |
| NG5 | Kosárszintű preferencia-minta mentés | v0.5+ — először termékszinten validáljuk |

## 5. User Stories

### Vásárló

**US-1:** Mint vásárló, amikor egy terméket a kosárba teszek, szeretném látni a releváns opciókat (pl. "Hogyan készítsük elő?") és kiválasztani a preferenciámat, mielőtt hozzáadom.

**US-2:** Mint visszatérő vásárló, amikor ugyanazt a terméket újra megnyitom, a rendszer ajánlja fel az előző választásomat default-ként, de lehetővé tegye a módosítást.

**US-3:** Mint vásárló, amikor az "Újrarendelem" gombot használom (DH-120), a korábbi rendelés preferenciái automatikusan betöltődjenek minden terméknél.

**US-4:** Mint vásárló, a kosárban látni akarom a kiválasztott opciókat minden terméknél (pl. "Sertés comb — 1 kg — szeletelve, vékony — pácolt").

**US-5:** Mint vásárló, ha nem akarok opciót választani, a rendszer egy ésszerű default-ot alkalmazzon (pl. "egész, pácolatlan") és ne blokkolja a rendelést.

### Admin / Mészáros

**US-6:** Mint admin, termékenként be akarom állítani, milyen opciók érhetők el (szeletelés, pácolás, stb.), és ezek értékeit.

**US-7:** Mint mészáros, a rendelés részletezőben világosan látni akarom a vásárló preferenciáit, hogy tudjam, hogyan készítsem elő a terméket.

## 6. Requirements

### P0 — Must Have

#### R1: Product Options konfigurálás (Admin)

Termékenként konfigurálható opciók a Frappe admin-ban:

- Új Child DocType: `Product Option` (parent: Product)
- Mezők: `option_name` (pl. "Felszeletelés"), `option_type` (single_select / multi_level / text), `values` (JSON array: ["Egész", "Szeletelt"]), `default_value`, `required` (bool), `display_order`
- Multi-level: ha "Szeletelt" van kiválasztva → megjelenik a második szint: ["Vékony", "Közepes", "Vastag"]

#### R2: Opció-választó UI a termékdetail oldalon

A termékdetail oldalon, a mennyiségválasztó alatt, a "Kosárba" gomb előtt:

- Cím: **"Cum să-ți pregătim?"** (Hogyan készítsük elő neked?)
- Opciók megjelenítése a `Product Option` konfiguráció alapján
- Ha nincs opció a termékhez → a szekció nem jelenik meg
- Default érték kiválasztva (admin által beállított VAGY user korábbi preferenciája)
- Nem kötelező opciók kihagyhatók

#### R3: Preferencia mentés per user per termék

- Új DocType: `User Product Preference`
- Mezők: `user`, `product`, `option_name`, `selected_value`, `last_updated`
- Trigger: Minden sikeres rendelés után a kiválasztott opciók mentődnek/frissülnek
- Bejelentkezetlen (guest) usereknél: nem mentődik (localStorage fallback opcionális P2)

#### R4: Preferencia betöltés

Amikor egy bejelentkezett user megnyit egy terméket:
1. Lekérdezés: van-e mentett preferencia ehhez a termékhez?
2. Ha igen → az opciók a mentett értékekkel jelennek meg default-ként
3. Ha nem → az admin által beállított default értékek
4. A user bármikor felülírhatja

#### R5: Kosár nézet — opciók megjelenítése

A kosárban minden terméknél a kiválasztott opciók megjelennek:
- Formátum: "Sertés comb — 1 kg — *szeletelve, vékony · pácolt*"
- Az opciók kisebb betűvel, dőlttel vagy szürke színnel — vizuálisan elkülönítve

#### R6: Rendelés részletező (Admin / Mészáros nézet)

A rendelés részletezőben (admin panel) minden terméknél kiírja a preferenciákat:
- Táblázatos formátum: Termék | Mennyiség | **Előkészítés**
- Az "Előkészítés" oszlopban a kiválasztott opciók (pl. "Szeletelve: vékony, Pácolt")
- Ha nincs opció: "Standard"

#### R7: Reorder kompatibilitás (DH-120)

Az "Újrarendelem" gomb használatakor:
- A korábbi rendelés preferenciái betöltődnek minden terméknél
- Ha a termék opciói megváltoztak (admin módosította) → a régi értéket mutatja, de jelzi, ha az opció már nem elérhető

### P1 — Should Have

#### R8: Opció módosítás a kosárban

A kosárban a termék opcióit szerkeszteni lehessen anélkül, hogy törölné és újra hozzáadná a terméket.
- Kattintás az opciókra → modal vagy inline szerkesztő

#### R9: Post-order Recap opció megjelenítés

A Post-order Recap (DH-119) megjeleníti a kiválasztott opciókat a termékek mellett.

### P2 — Nice to Have

#### R10: Guest user preferencia (localStorage)

Bejelentkezetlen usereknél a preferenciák localStorage-ban mentődnek, és bejelentkezéskor átmigrálódnak a szerver-oldali DocType-ba.

#### R11: "Leggyakoribb választás" jelzés

Ha egy opciónál az adatok mutatják, hogy a vásárlók többsége (>70%) ugyanazt választja → "Leggyakrabban választott" badge.

## 8. Adatmodell

### User Product Preference DocType

```
user            → Link (User)
product         → Link (Product)
preferences     → JSON
  {
    "Tăiere": "Feliat - Subțire",
    "Marinare": "Nemarinate"
  }
last_updated    → Datetime
source          → Select (order / manual)
```

### Product Option Child DocType

```
option_name     → Data (pl. "Tăiere")
option_type     → Select (single_select / multi_level / text)
values          → JSON (pl. ["Întreg", "Feliat"])
sub_values      → JSON (pl. {"Feliat": ["Subțire", "Mediu", "Gros"]})
default_value   → Data
required        → Check (0/1)
display_order   → Int
```

## 9. Firebase Analytics events

| Event | Trigger | Params |
|-------|---------|--------|
| `product_option_selected` | User kiválaszt egy opciót | `product_id`, `option_name`, `value` |
| `product_option_changed` | User megváltoztatja az opciót (nem default) | `product_id`, `option_name`, `old_value`, `new_value` |
| `preference_loaded` | Mentett preferencia betöltődik | `product_id`, `preference_count` |
| `preference_overridden` | User felülírja a mentett preferenciát | `product_id`, `option_name` |

## 11. Kockázatok

| # | Kockázat | Hatás | Mitigáció |
|---|----------|-------|-----------|
| 1 | Túl sok opció → döntési paralízis | Lassabb rendelés, alacsonyabb konverzió | Max 3 opció termékenként; default mindig van |
| 2 | A mészáros nem olvassa az opciókat | Rossz előkészítés → trust break | Admin UI-ban kiemelten, nyomtatható rendelési lap |
| 3 | Opció-választás lassítja a flow-t | TTFO nő | Opciók opcionálisak, default értékkel |
| 4 | Visszatérő user preferencia outdated | Nem elérhető opció → hiba | Graceful fallback: "Ez az opció már nem elérhető" |
