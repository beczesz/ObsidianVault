# DH v0.3 — A spórolás motora

## Core Definíció

> **A DH egy döntéstámogató rendszer, amely optimalizálja a vásárlói döntéseket és a háttérben a termelést, logisztikát és készletet — az ebből származó margin előnyt pedig visszaadja a felhasználónak.**

**Alapelv:** Nem kedvezményt adunk. Nem akciózunk. Nem olcsóbbak vagyunk. → **Jobb döntést segítünk hozni.**

**Stratégiai pozíció:** ❌ Webshop · ❌ Marketplace · ❌ Discount platform → ✅ **Optimalizáló rendszer** (supply + demand)

## Sprint 2 KÉSZ ✅ — Sprint 3 ACTIVE

> **Sprint 2 LEZÁRVA 2026-04-15** — 38/38 ticket Done (100%). v0.2 "Látjuk az adatokat" analytics infrastruktúra telepítve: Firebase Analytics, UTM/QR forráskövetés, KPI dashboard. **Sprint 3 indul 2026-04-16** (MUST/SHOULD/COULD prioritás: lásd `sprint-3-prioritization-2026-04-15.md`).
>
> ⚠️ **Beta korrekció:** A valódi beta launch **v0.3 release UTÁN** (~2026-05-15, Sprint 3 végén). A beta NEM indult el ápr. 14-17-ben.

## Stratégiai cél

A v0.3 a webshopból döntéstámogató rendszerré alakítja a DH-t. A core loop validálása max 6-7 feature-rel.

A v0.3 NEM a Phase 2 (multi-supplier) — hanem a Phase 1 tökéletesítése.
Ha a v0.3 végén a számok jók, az lesz a playbook a következő termelőhöz.

> **Notification constraint:** Nincs SMS (drága), nincs push (nincs natív app). Minden notification = email + in-app. Push → v0.5.

## Rendszer architektúra — 4 réteg

| Réteg | Név | Feature-ök | Cél |
|-------|-----|-----------|-----|
| 🔴 L1 | **Decision Engine** (Core UX) | Savings counter, threshold nudge, post-order recap | Döntési feedback loop |
| 🟠 L2 | **Basket Optimization** | Családi csomagok, swap suggestion (minimal supply hook) | Valódi optimalizáció |
| 🟡 L3 | **Habit Engine** | 1-click reorder, "Szokásos rendelésem" | Ismétlődő viselkedés |
| 🔵 L4 | **Activation & Recovery** | TTFO engine, post-delivery trigger, savings recap email | Aktiváció + visszahozás |

## Core Loop

```
Kosár építés → Progress → Ajánlás → Visszajelzés → Újrarendelés
```

| Lépés | Mi történik | Feature |
|-------|-------------|---------|
| 1. Kosár építés | User termékeket ad hozzá | Terméklista + kosár |
| 2. Progress | "Még X RON → jobb döntés" | Savings counter + threshold nudge |
| 3. Ajánlás | Threshold, bundle, swap | Családi csomag + swap |
| 4. Visszajelzés | "X RON-t optimalizáltál" | Post-order recap |
| 5. Újrarendelés | 1-click reorder + trigger | Reorder + email trigger |

## Savings → Feature mapping

| Margin leakage forrás | Feature | Réteg |
|-----------------------|---------|-------|
| Logisztika (delivery költség) | Threshold nudge | L1 |
| Mennyiség (batch inefficiency) | Bundle / családi csomag | L2 |
| Carcass balance | Swap suggestion | L2 |
| Idő / frissesség | "Ma ajánlott" (future — nem v0.3) | — |
| Demand stabilizálás | Reorder | L3 |

## v0.3 fókusz — Max 6-7 feature

A cél a core loop validálása, nem feature overload:

1. **Savings counter** (L1)
2. **Threshold nudge** (L1)
3. **Post-order recap** (L1)
4. **1-click reorder** (L3)
5. **Családi csomagok** (L2)
6. **Swap suggestion — MVP** (L2)

> **Siker definíció:** A felhasználó érzi, hogy: "jobban vásároltam, mint legutóbb." Ha ez teljesül → repeat jön → AOV nő → rendszer skálázódik.
